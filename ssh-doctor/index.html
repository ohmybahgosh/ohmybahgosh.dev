SSH Doctor
for rooted LG webOS TVs

SSH broke?
Fix it from the couch.

SSH on a rooted LG TV breaks in a handful of ways: a keys file with Windows line endings, a private key pasted by mistake, the alpine password gone after the first key, a host key warning after a reset. SSH Doctor finds out which one, in plain words, and fixes it with the remote. It runs through the Homebrew Channel, not over SSH, so it still works when SSH is completely broken. It also pairs a key from your phone or computer with a short code, and lets you set your own password, switch to keys only or move SSH to another port, all kept after a restart. Use Entware's OpenSSH or dropbear instead? It checks that too.

features

Check, fix, pair.

Every repair says what it will change and keeps a dated backup first.

The check

Whether SSH is on in the Homebrew Channel and really running on its port, how you can log in (password, keys, or nobody), whether authorized_keys is usable, telnet as a way back in, failsafe mode, and the TV's own key fingerprints.

One button per fix

Turn SSH on now without a restart, Fix my keys file (line endings, hidden characters, wrapped and PuTTY keys, private keys, permissions), Go back to password login for anyone locked out, and Undo a change.

QR

Pair a key by code

Scan the QR on the TV, type the short code, and send a key you have or let the browser make one. The private key never leaves your phone or computer.

Entware's SSH too

When Entware's OpenSSH or dropbear is how you log in, it counts as your SSH and gets checked: its settings, root login, whether a password works there, host keys, its port and starting at boot. It also spots Developer Mode's SSH on 9922, and only ever changes the Homebrew Channel's server.

$_

Works over telnet too

ssh-doctor.sh runs on its own, for when telnet is the only way in: status, fix-keys, password-on and the rest.

dropbear -p 2222 -s -K 30

SSH settings that stick.

dropbear has no settings file: its options are set when it starts, and the Homebrew Channel starts it with none. SSH Doctor keeps yours and puts them back after every restart, with a small startup script in /var/lib/webosbrew/init.d.

***

Your own password

Typed on the TV, or on your phone through the pairing page. It's turned into a SHA-512 crypt hash first, so the password itself is never sent over your network or saved on the TV, and applied the way the Homebrew Channel applies alpine.

#

Keys only

Passwords stop logging in. It won't turn on until a key is on the TV, and Go back to password login undoes it if you lose the key.

:22

Another port

2222, 22022 or any free port. The old port stays open until you've logged in on the new one and keep it, and if dropbear won't start there, SSH goes straight back.

♥

Keepalive and reset

A keepalive every 30 seconds so routers don't drop quiet sessions, and Reset to Homebrew Channel defaults removes all of it, the startup script too.

more tools

Who's been logging in?

Recent logins and failed tries from the TV's own log, with a warning when the tries come from outside your home network.

Keys on this TV

Each key with its name, fingerprint and when it last logged in. Rename or remove one, with a backup.

The TV's own keys

Fingerprints to check a first login against, or make new ones if they're broken.

Telnet off

The Homebrew Channel's telnet lets anyone on your network in as root with no password. Turn it off once SSH works, or back on.

Report for help

A QR code with a short report, no addresses, keys or names in it, ready to paste into a GitHub issue or a forum post.

set up a key

No copying keys around.

The pairing page only runs while its screen is open on the TV, and nothing changes until you press OK on the remote.

Choose Set up a key

The TV shows a QR code, an address on port 28622 and a short code like K7F-3QX.

Scan it and type the code

On the phone or computer you'll log in from. Five wrong tries get a new code, and three rounds close the page.

Send a key, or make one

Upload the .pub file you have, or let the browser make an ed25519 key pair. Only the public half goes to the TV.

Check the fingerprint, press OK

The page then shows the exact command for Mac, Linux, Windows, PuTTY, SFTP or a phone app, plus a ready-made ~/.ssh/config entry and the TV's known_hosts lines.

Exactly what it changes.

Only when you press a button, with a backup first. System partitions are never written.

pathwhat
/home/root/.ssh/authorized_keysRepaired, added to, or set aside, always with a dated .ssh-doctor-* backup next to it
/etc/shadowNever written: root's password goes through a bind-mounted copy in /tmp, the way the Homebrew Channel sets alpine
/var/lib/webosbrew/ssh-doctorYour SSH settings, and your password's hash (readable by root only)
/var/lib/webosbrew/init.d/60-ssh-doctorStartup script that restarts the Homebrew Channel's dropbear with your settings. Only there while a setting is on
/var/luna/preferences/webosbrew_*The Homebrew Channel's own SSH and telnet switches, only when you turn them on or off
/var/lib/webosbrew/sshdThe TV's host keys, only if you make new ones (backed up first)
/opt/etcEntware's SSH settings, host keys and password file: only read, never changed. OpenSSH is asked for its settings with sshd -T, which only reads them
faq

Questions.

I added a key and now alpine doesn't work. Is something broken?
No, that's the Homebrew Channel on purpose: at startup it only turns alpine on when there's no keys file. If the key doesn't work either, open SSH Doctor and choose Fix my keys file, or Go back to password login.
Can I lock myself out with the settings?
It's hard to. Keys only won't turn on without a key, a port change keeps the old port open until you keep the new one, and the app itself runs through the Homebrew Channel, so Go back to password login always works from the remote.
Does my password go over the network?
No. The TV app or the pairing page turns it into a SHA-512 crypt hash first, and only the hash is sent and kept.
I use Entware's OpenSSH. Will it touch that?
It never changes, starts or stops it. When Entware's OpenSSH or dropbear is how you log in, SSH Doctor treats it as your SSH and checks it: whether OpenSSH accepts its settings, whether root may log in, whether a password works there (OpenSSH turns root's password off by default, and Entware keeps its own password file, /opt/etc/shadow), its host keys, its port, and whether Entware starts at boot. Set up a key works for it too, since it reads the same keys file.
Was this written by AI?
It's written with AI coding agents (Claude), directed, reviewed and tested by me. The script has a test suite that runs every check and repair against a fake TV under busybox sh, dash and bash, CI drives the TV app and the pairing page in a browser, and each release is tried on a real TV.
