LG-USB-2-ETH0
for rooted LG webOS TVs

Your TV's
fast lane is eth0.

LG TVs ship with a 100 Mbit/s wired port. A USB gigabit adapter is two to three times faster, even on a USB 2.0 port like the one on a 2022 C2, but webOS calls it eth1 and ignores it. LG-USB-2-ETH0 makes the adapter the TV's eth0, safely and at every boot. Use the TV app from the Homebrew Channel, no SSH needed, or the same script over SSH. It can also find, check and install a faster driver for Realtek and ASIX adapters on your exact TV, test new drivers built for many more TVs, and block firmware updates harder so an update doesn't take root away.

what it fixes

Three problems, one rename.

Streaming apps fail

Apps like Paramount+ refuse to play over eth1. The adapter becomes eth0, so they play.

"Not Connected"

webOS settings show no wired connection while the adapter works. Interface names now match what webOS expects.

100 Mbit/s ceiling

High-bitrate remuxes, Plex and Moonlight stutter on the built-in port. The adapter does 250 to 330 Mbit/s.

get-driver

The right driver, found and fitted for you.

Many TVs hand Realtek adapters to the generic cdc_ncm driver, which is slower and drops out under load. Some TVs have no driver for the chip at all: LG removed the Realtek driver from 2024 QNED and OLED models, and some TVs have no ASIX driver. The firmware audit lists which drivers each model's kernel has, read from LG's own firmware. LG-USB-2-ETH0 checks whether a driver is known for your exact TV and adapter, then downloads, checks and sets it up for you. In the TV app it's one switch: Faster driver.

Checks your TV

A driver is only offered for the exact kernel it was built for, and only when an adapter it supports is plugged in. The adapter's USB ID is checked against the driver's own list.

Downloads and verifies

From a fixed commit of the driver author's repository, kept only if its SHA-256 matches. If the author's copy is gone, from the same file in the lg-webos-usb-drivers mirror, with the same check. A driver built for another kernel is refused before it's loaded.

Moves the adapter over

Releases the adapter from the generic driver and binds it to the new one. An adapter with no driver at all just picks it up. On Realtek's driver, scatter-gather is turned off so the TV's USB controller doesn't hang. If it doesn't take within a few seconds, the adapter goes back.

Keeps it there

At every boot, and after standby, which resets the TV's USB ports and drops a Realtek adapter back to the slow driver. One try per boot, so it can't cause repeated drops. A phone tethered over USB is never touched.

Drivers for many more TVs, waiting for testers.

Picks the build

For your kernel, your chip and the adapter plugged in. One kernel name can run on several Realtek chips with different configs, so there's a build per chip.

Loads it for now only

Downloaded from a fixed commit, kept only if its SHA-256 matches and it's built for exactly your kernel. Nothing loads it at boot, so a restart puts the TV back as it was.

Checks and reports

Moves the adapter to it, waits for it to get online and pings out. Then a QR code opens a filled-in test report on your phone, with no MAC or IP addresses. If the driver froze the TV, the next run says so and reports that too.

$ sh LG-USB-2-ETH0.sh test-driver

Or in the TV app: a Test a new driver row shows up when your TV runs one of these kernels. The full list, kernel by kernel and chip by chip, with each module's checks: lg-webos-usb-drivers. How they're built: driver-build.md. Thanks to DonZoomik for the method and OCT0PUSCRIME for the 32-bit build steps.

--block-updates

Block updates harder.

A firmware update can remove root, and current firmware can't be rooted again. The Homebrew Channel's Block system updates is the first line. People in Homebrew Channel issue #96 found what it misses, and Block updates harder adds that on top. It never replaces the Homebrew Channel's block or changes its setting.

Turns off webOS's own update check

A hidden webOS setting, the same switch Homebrew Channel PR #264 turns off, including the check webOS makes early in boot, before the Homebrew Channel's block is in place.

Blocks the servers the Homebrew Channel misses

nsu.lge.com, snu-dev.lge.com and ngfts.lge.com, in /etc/hosts. If the Homebrew Channel's block is off, it blocks that block's four servers too.

Drops traffic to LG's update IP

The updater also reaches one server by IP, which no hosts file can block, so one firewall rule drops it.

Clears cached update details

Anything already found or downloaded is deleted, so a waiting update prompt goes away.

It does this right away and again at every boot. Turning it off, or Turn everything off, undoes only its own changes, and the Homebrew Channel's setting stays as you left it. status points out when nothing blocks updates, or when only the Homebrew Channel's block does. Tested on a C2 with webOS 25.

$ sh LG-USB-2-ETH0.sh install --block-updates
About webOS 26. LG has started rolling out webOS 26 to 2022 to 2025 models, and it patches the known root methods, like the rest of LG's current firmware. Keep Automatic software updates off in the TV's settings and Block system updates on in the Homebrew Channel. If a TV still shows the update prompt, block the servers listed in Homebrew Channel issue #96 on your router or Pi-hole. Check where your firmware stands at CanI.RootMy.TV. People keep looking for new ways in, and each new root method came along after the one before it was patched, so one for webOS 26 may still turn up.
--wifi-wake

Turn it on over the network.

Wake on LAN, Turn on via Wi-Fi, the ThinQ app and Home Assistant can't wake the TV through a USB adapter: standby resets the USB ports. LG's wake listens on Wi-Fi. But with an adapter in, some TVs drop off Wi-Fi in standby, some turn Wi-Fi off at boot, and webOS can move your traffic to Wi-Fi once it's back. Wi-Fi wake in standby handles all three.

Keeps Wi-Fi ready, and the adapter first

While the TV is on, it keeps Wi-Fi on and joined to your saved network, and keeps the adapter ahead of Wi-Fi so traffic goes over the cable. Every 10 seconds it checks the internet hasn't moved to Wi-Fi.

Hands over just before standby

If Wi-Fi is connected and Turn on via Wi-Fi is on, it disconnects only the adapter's network session. The adapter stays plugged in and stays eth0.

Takes it back on wake

When the TV is on again, or at the next boot after a power cut, it connects the adapter again and puts it ahead of Wi-Fi. Up to 10 tries, since the adapter takes a few seconds to come back.

Logs every step

Each power state, hand-over and try goes in /var/lib/webosbrew/lg-usb-2-eth0.log, with why it did or didn't hand over.

Turn on Turn on via Wi-Fi in the TV's settings and join your Wi-Fi once. Then switch on Wi-Fi wake in standby in the app. It starts right away, no restart needed. Wake the TV by its Wi-Fi MAC, which status prints, sent to your network's broadcast address on port 9. Tested on a 2022 C2 and a G6 on webOS 26.

$ sh LG-USB-2-ETH0.sh install --wifi-wake
Fixed IPs? Give Wi-Fi its own address, not the adapter's. Two connections with the same IP break the TV's connection, so it disconnects Wi-Fi if it finds that, and status warns. upgrade from v1 · 2.4.1 and later

Upgrading from v1.

Still on v1 of the script? No SSH needed. Install the app from the Homebrew Channel and open it. It finds your old boot hook and shows Upgrade from v1 at the top of the menu. Press OK and it walks you through three steps.

What's there now

Where the v1 hook is and what it does at every boot, whether your adapter is eth0 right now, and that the upgrade doesn't touch the network.

What changes

The v1 hook is replaced in place by this version's, which follows the app's updates. Nothing switches now, the new hook only acts when an adapter is plugged in, and Turn everything off undoes it all.

Upgraded and checked

The app upgrades, then checks the new hook is in place, the old v1 file is gone, and the adapter is still eth0. If anything didn't work, it says what and points you to Report for GitHub.

The adapter stays eth0 the whole time, nothing switches until the next boot, and from then on updates come through the Homebrew Channel.

ssh quick start

Prefer SSH?

The TV app is the easiest way in. This is the same thing without it. You need a rooted LG TV with the Homebrew Channel, SSH as root, and a Wi-Fi connection while you set this up, since renaming takes the wired ports down for a moment.

$ cd /tmp
# download the latest release and its checksum
$ curl -fsSLO https://github.com/ohmybahgosh/LG-USB-2-ETH0/releases/latest/download/LG-USB-2-ETH0.sh
$ curl -fsSLO https://github.com/ohmybahgosh/LG-USB-2-ETH0/releases/latest/download/SHA256SUMS
$ sha256sum -c SHA256SUMS
# read-only look at the TV first
$ sh LG-USB-2-ETH0.sh status
# install the boot hook (asks before it writes), then switch now
$ sh LG-USB-2-ETH0.sh install
$ sh LG-USB-2-ETH0.sh apply

No curl? Use wget the same way. On a TLS error, download on your computer and copy over with scp.

real speeds

Not gigabit. Still 3x.

The TV's USB port is the limit, so don't expect gigabit. On a C2 at full speed the busiest CPU core was only about a third busy. But two to three times the built-in port is plenty for 4K remuxes.

Measured by DonZoomik (webos-r8152), lgwebos.com users, owners of a G4 and a UN7300, and on the author's C2.

how it works

One hook. Nothing else touched.

At boot the Homebrew Channel runs everything in /var/lib/webosbrew/init.d. LG-USB-2-ETH0 adds one hook there, a link to the script, and keeps its settings in /var/lib/webosbrew/lg-usb-2-eth0.conf, so updates never lose them. It only renames network interfaces. No system files are touched, and network settings only if you turn on the Wi-Fi backup, Wi-Fi wake in standby or Block updates harder, so a reboot without the hook always starts clean.

Undo everything: Turn everything off in the TV app, or sh LG-USB-2-ETH0.sh uninstall --now

Returns at once

Starts in the background so other hooks and the failsafe timer aren't held up.

Waits for a real adapter

Only wired Ethernet on USB counts. Wi-Fi, phones and modems are skipped. No adapter, no changes.

Optional faster driver

With --module, moves the adapter from generic cdc_ncm to a better driver, with one try per boot and an automatic fallback.

Swaps the names

Built-in eth0 becomes eth2, the adapter becomes eth0. Interrupted renames retry, and failures roll back.

Follows hotplug

With --watch, plug the adapter in or out any time and eth0 follows it.

Survives standby

Standby resets the TV's USB ports and drops the adapter back to cdc_ncm. With --module, the hook moves it to the faster driver again. The check costs next to nothing.

Keeps Wi-Fi as a backup

With --wifi-fallback, if eth0 has no cable link for a minute while Wi-Fi is off, it turns Wi-Fi on so the TV joins a network it knows, and turns it off again 30 seconds after the cable is back. It only turns off what it turned on.

Keeps Wi-Fi wake working

With --wifi-wake, it follows the TV's power state. Just before standby, if Wi-Fi is connected and network wake is on, it disconnects the adapter's session in webOS's connection manager so Wi-Fi stays ready for Turn on via Wi-Fi, and connects it again on wake, ahead of Wi-Fi. A power cut in standby is handled at the next boot.

Blocks updates again

With --block-updates, before anything else, it turns webOS's update check off and blocks LG's update servers again, since the hosts entries and firewall rule don't survive a reboot.

compatibility

The chip matters more than the brand.

What decides whether it works is whether your TV's kernel has a driver for your adapter's chip. Run status before buying: it lists the USB network drivers your kernel has.

RTL

Realtek 8153 / 8156

The most common gigabit and 2.5G chips. Newer kernels may only offer generic cdc_ncm, which works but is slower. get-driver fixes that on the C2, C3, C4, G4 and UR9000. 2024 and 2025 Realtek-chip TVs on current firmware still need one built.

AX

ASIX AX88179

Works out of the box on many TVs, like a 2024 G4 on webOS 25. Where the kernel has no ASIX driver, like a 2020 UN7300, a 2024 B4 or QNED85, a 2025 B5 or a K5Lp TV, get-driver offers one.

USB

USB 2.0 is fine

Many TVs, like the 2022 C2, only have USB 2.0 ports. That tops out around 300 Mbit/s: still about 3x the built-in port and faster than Wi-Fi. Use USB 3.0 if your TV has it, and a powered hub for fussy adapters.

faq

Questions.

Was this written by AI?
Partly, and openly. I wrote v1 by hand. From v2.0 on it's written with AI coding agents (Claude), directed, reviewed and tested by me. Nothing ships until it's run on a real TV (an LG C2 on webOS 25), and the fixes that mattered most came from that testing: standby putting the adapter back on the slow driver, and webOS quietly using Wi-Fi instead of the adapter. 90 tests run on every push, downloads are checked by SHA-256, and no system files are touched. The driver modules come from DonZoomik, mbenitez343, OCT0PUSCRIME, dd3git and throwaway96, not from AI. How these are built.
Does it survive a firmware update?
The hook lives in the Homebrew Channel's folder, so it stays as long as root does. If an update removes root, the hook stops running and the TV just goes back to the built-in port. Current firmware, webOS 26 included, can't be rooted again, so keep updates off: see Block updates harder.
Does it change my network settings?
No. webOS still sets up the wired connection itself. The script only changes which device is called eth0. The exceptions are the Wi-Fi backup, if you turn it on: it flips the Wi-Fi switch on when the cable stops working, and back off when it works again. And Wi-Fi wake in standby: it disconnects the adapter just before standby and connects it again on wake. --block-updates doesn't change your network either, but it does add LG's update servers to /etc/hosts and one firewall rule.
Lost SSH while switching?
The switch still finishes on the TV. Reconnect over Wi-Fi. The adapter has its own MAC, so your router may hand out a new IP; a DHCP reservation keeps it steady.
Can I use two adapters?
Yes. Pin the one you want with --mac. Without it, the first adapter with a cable in wins.
