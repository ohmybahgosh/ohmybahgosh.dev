pipseek
pip search, brought back

Search all of PyPI.
From your terminal.

pip search was switched off years ago, and PyPI's search page now sits behind a browser challenge. pipseek keeps its own full-text index of every project on PyPI, searches it locally in about 100 ms, even offline, and pulls live details for the results you're looking at. It also checks your own environment for outdated and vulnerable packages. Public APIs only: no scraping, no accounts, no keys.

pipseek --help

Find the package. Check the ones you have.

Search by what a package does, not just its name, then see what's outdated or vulnerable in your own environment.

Searches descriptions

Full-text search over every project's name, summary and keywords. pipseek "progress bar" finds tqdm, pipseek "web framework" finds Django, Flask and Tornado, and pipseek requests still puts requests first.

Ranked the way you'd expect

Exact and prefix name matches, BM25 relevance over descriptions, and real 30-day download counts, so popular packages beat empty placeholders named after your search.

Version, release age, downloads, stars, open issues, the OpenSSF Scorecard, license, Python requirement, links, extras and dependencies. Text from PyPI is always shown as plain text, so a package can't hide links, fake badges or crash a search.

install

One command.

pipx or uv keep pipseek in its own isolated environment, which is the cleanest way. Plain pip works too.

$ pipx install pipseek
$ pipseek "web framework"
$ pipx upgrade pipseek         # later
$ uv tool install pipseek
$ pipseek "web framework"
$ uv tool upgrade pipseek      # later
$ pip install pipseek
$ pipseek "web framework"
$ pipx install git+https://github.com/ohmybahgosh/pipseek

The latest code from GitHub instead of the PyPI release.

The first run downloads the search index (about 35 MB), checks it against its published SHA-256 checksum and builds a local database from it, which takes about 10 seconds and peaks around 60 MB of memory. After that it checks once a day whether a newer index is out, using its tiny checksum file, and downloads it only when it changed, so new packages show up within about a day. --refresh downloads it again right away. Upgrading from the v1 script? Remove the old /usr/local/bin/pipseek first so it doesn't shadow the new command.

pipseek --outdated

What's out of date. What's vulnerable.

pipseek --outdated checks every package in your environment against PyPI and OSV.dev, puts the vulnerable ones first, and ends with the upgrade command.

$ pipseek --outdated            # worst first
$ pipseek --outdated --all      # every package
$ pipseek --outdated --json     # for scripts
$ pipseek --outdated --strict   # fail CI if vulnerable
$ pipseek --outdated --no-stats # skip OSV.dev
--strict exitmeaning
0Nothing installed is known to be vulnerable
1Something installed has a known vulnerability
2Some lookups failed, so the check is incomplete

It checks the same environment pipseek uses for installed badges: your active virtualenv, otherwise the first python3 on your PATH, or whatever you pass to --python. When a lookup fails, it says which packages it couldn't check instead of calling them safe: in --json, "vulnerabilities": null means unknown and [] means none are known. --no-stats skips the vulnerability checks and can't be combined with --strict, and --all and --strict only work with --outdated. On an OS-managed system Python, it still reports, but won't suggest pip install or install anything.

cat how-it-works

Its own index, rebuilt daily.

PyPI has no public full-text search API, so pipseek brings its own.

A daily GitHub Action

The PyPI Simple API reports a change serial for every project, so the build only re-fetches what changed since yesterday, and publishes the index with its SHA-256 checksum. A weekly watchdog checks that it's fresh and keeps the daily job switched on.

A local SQLite database

Once a day, pipseek checks whether that file changed. When it did, pipseek downloads it, checks its checksum and streams it into an FTS5 full-text database. A download that's corrupt, oversized or mostly missing summaries is rejected, and the database you already have is kept.

Each search

Name matches, BM25 relevance over summaries and keywords, and 30-day download counts, then live details for just the page you're viewing, cached for an hour.

A fallback that ships inside

If the index can't be reached, pipseek uses every project name from PyPI plus summaries for the 15,000 most popular projects, and tries again the next day.

faq

Questions.

Why not just use pypi.org/search?
You can in a browser, but it can't be scripted any more: it sits behind a JavaScript challenge meant to stop bots. pipseek doesn't try to get around it. It uses PyPI's official APIs instead, which are made for tools.
How fresh are the results?
The index is rebuilt every day, and pipseek checks for a new one every day, so a package published today shows up in search within a day or so. Offline, pipseek keeps using its copy and rebuilds it after a week. Versions, release dates and stats for the results you look at are live, cached for an hour.
How much disk space does it use?
About 175 MB for the search database, in ~/.cache/pipseek on Linux, ~/Library/Caches/pipseek on macOS, or %LOCALAPPDATA%\pipseek on Windows. pipseek --clear-cache removes it, along with everything else pipseek has cached.
Does it work offline?
Yes, once the index is built. Searching is local. For details, pipseek uses anything it has cached, and otherwise shows the name and summary from the local index with a note that PyPI couldn't be reached. --info works the same way.
Can I use my own index?
Yes. python -m pipseek.build_index --out pypi-index.tsv.gz builds one from PyPI's JSON API, over several runs the first time. Point PIPSEEK_INDEX_URL at it: an http(s) URL, a file:// URL or a local path.
Is pipseek --outdated a replacement for pip-audit?
For a quick look, often yes: it uses the same OSV data and adds what's outdated. pip-audit goes further for CI pipelines (requirements files, SBOMs, auto-fixing), so use it when you need those.
Does it change anything on my system?
No. pipseek only reads public data and writes to its own cache folder. The one exception is the i key in the TUI, which runs pip install after showing you the exact command, and refuses on an OS-managed Python.
Was this written by AI?
v1 (early 2025) was one script I wrote that scraped PyPI's search page. v2 is a ground-up rewrite with AI coding agents (Claude), directed, reviewed and tested by me. On every push, CI runs pytest and ruff on Python 3.9, 3.13 and 3.14 on Linux, macOS and Windows, and builds the package. How these are built.
