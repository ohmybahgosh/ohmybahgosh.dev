webOS luna-send command cheatsheet

A grouped, copy-paste list of real luna-send commands for a rooted LG webOS TV: power, apps, sound, picture, notifications, inputs, channels, settings, network, Bluetooth, storage, screenshots, developer tools, IR and the service menu. Every command is checked against the Luna Atlas catalog.

71 commands, grouped by task. Every one has a copy button, runs on a rooted LG webOS TV over SSH or in Developer Mode, and is checked against the Luna Atlas catalog. Calls that change or reset things are flagged ⚠ dangerous.

Running commands

luna-send is on every webOS TV; you reach it over SSH on a rooted set or in Developer Mode. -n 1 waits for one reply then exits, -f prints it formatted, and -i stays subscribed and streams updates until Ctrl-C. A few calls are only on the public bus, where you use luna-send-pub. Private methods need root; Developer Mode's shell is not root.

Call shape

$ luna-send -n 1 -f luna://<service>/<method> '{"key":"value"}'

Stay subscribed to updates subscribe

$ luna-send -i -f luna://<service>/<method> '{"subscribe":true}'

Power & screen

Read or watch the power state, turn just the panel off while sound keeps playing, and reboot.

Watch the power state live subscribe

$ luna-send -i -f luna://com.webos.service.tvpower/power/getPowerState '{"subscribe":true}'

Turn the panel off (backlight only, audio keeps playing)

$ luna-send -n 1 -f luna://com.webos.service.tvpower/power/turnOffScreen '{}'

Turn the panel back on

$ luna-send -n 1 -f luna://com.webos.service.tvpower/power/turnOnScreen '{}'

Screen off that sticks like the remote's own option

$ luna-send -n 1 -f luna://com.webos.settingsservice/setSystemSettings '{"category":"picture","settings":{"energySaving":"screen_off"}}'

Open the energy-saving / screensaver screen luna-send-pub

$ luna-send-pub -n 1 -f luna://com.webos.service.applicationManager/launch '{"id":"com.webos.app.tvhotkey","params":{"activateType":"energy-saving-mode"}}'

Reboot the TV ⚠ dangerous

$ luna-send -n 1 -f luna://com.webos.service.tvpower/power/reboot '{"reason":"luna-send"}'

Power the TV off ⚠ dangerous

$ luna-send -n 1 -f luna://com.webos.service.tvpower/power/powerOff '{"reason":"luna-send"}'

"Stealth" reboot (not logged the way a normal reboot is) ⚠ dangerous

$ luna-send -a webosbrew -f -n 1 luna://com.webos.service.sleep/shutdown/machineReboot '{"reason":"remoteKey"}'

Apps & launcher

See what's on screen, launch and close apps, and list what's installed.

Show the foreground app, and each time it changes subscribe

$ luna-send -i -f luna://com.webos.applicationManager/getForegroundAppInfo '{"subscribe":true}'

Launch an app by ID ⚠ dangerous

$ luna-send -n 1 -f luna://com.webos.applicationManager/launch '{"id":"com.webos.app.browser"}'

Launch an app with parameters ⚠ dangerous

Jump to the Home launcher ⚠ dangerous

$ luna-send -n 1 -f luna://com.webos.applicationManager/launch '{"id":"com.webos.app.home","params":{"activateType":"powerOn"}}'

Close an app by ID

$ luna-send -n 1 -f luna://com.webos.applicationManager/closeByAppId '{"id":"com.webos.app.hdmi3"}'

List every installed app needs root

$ luna-send -n 1 -f luna://com.webos.applicationManager/listApps '{}'

List the launcher tiles (launch points)

$ luna-send -n 1 -f luna://com.webos.applicationManager/listLaunchPoints '{}'

Get one app's metadata

$ luna-send -n 1 -f luna://com.webos.applicationManager/getAppInfo '{"id":"com.webos.app.livetv"}'

Check whether an app is running needs root

$ luna-send -n 1 -f luna://com.webos.applicationManager/getAppStatus '{"appId":"com.webos.app.browser","appInfo":true}'

Settings: read & write

The settings service reads and changes almost everything the on-screen menus do. Categories include picture, sound, option, time and network.

Read any setting

$ luna-send -n 1 -f luna://com.webos.settingsservice/getSystemSettings '{"category":"option","keys":["country"]}'

Write a setting

$ luna-send -n 1 -f luna://com.webos.settingsservice/setSystemSettings '{"category":"option","settings":{"audioGuidance":"off"}}'

Read a setting's description / allowed values

$ luna-send -n 1 -f luna://com.webos.settingsservice/getSystemSettingDesc '{"category":"picture","keys":["pictureMode"]}'

Stop the 15-minute no-signal auto power-off

$ luna-send -n 1 -f luna://com.webos.settingsservice/setSystemSettings '{"category":"time","settings":{"autoOff15Min":"off"}}'

Turn off mobile (SSAP) access after rooting

$ luna-send -n 1 -f luna://com.webos.settingsservice/setSystemSettings '{"category":"network","settings":{"allowMobileDeviceAccess":false}}'

Screenshots

Capture the current frame to a file. The service was renamed from com.webos.service.tv.capture to com.webos.service.capture on newer sets; the call is the same. Formats: BMP, JPG, PNG, RGB, RGBA, YUV422. Methods: DISPLAY (the UI), SCREEN_WITH_SOURCE_VIDEO, VIDEO, GRAPHIC. Defaults to 960x540.

Capture to /tmp (default size)

$ luna-send -n 1 -f luna://com.webos.service.capture/executeOneShot '{"path":"/tmp/capture.png","method":"DISPLAY","format":"PNG"}'

Capture at full 4K

$ luna-send -n 1 -f luna://com.webos.service.capture/executeOneShot '{"path":"/tmp/capture.png","method":"DISPLAY","format":"PNG","width":3840,"height":2160}'

Capture with the date in the filename

$ luna-send -n 1 -f luna://com.webos.service.capture/executeOneShot "{\"path\":\"/home/root/cap_$(date +%Y-%m-%d_%H-%M-%S).png\",\"method\":\"DISPLAY\",\"format\":\"PNG\"}"

Older sets (renamed service) needs root

$ luna-send -n 1 -f luna://com.webos.service.tv.capture/executeOneShot '{"path":"/tmp/capture.png","method":"DISPLAY","format":"PNG"}'

Alternate compositor capture

$ luna-send -n 1 -f luna://com.webos.surfacemanager/captureCompositorOutput '{"output":"/tmp/screenshot.jpg","format":"JPG"}'

Developer & logging

Install apps, turn on developer logs and read them. The PmLogCtl and tail lines are plain shell, not luna-send.

Install an IPK already on the TV subscribe

$ luna-send -i -f luna://com.webos.appInstallService/dev/install '{"id":"com.example.app","ipkUrl":"/media/internal/downloads/app.ipk","subscribe":true}'

Turn on developer logging ⚠ dangerous

$ luna-send -n 1 -f luna://com.webos.service.config/setConfigs '{"configs":{"system.collectDevLogs":true}}'

Set one component's log level shell

$ PmLogCtl set <context> debug

Follow the logs for an app shell

$ tail -F /var/log/messages | grep <app-or-context>

Turn Developer Mode on (reboots the TV) ⚠ dangerous

$ luna-send -n 1 -f luna://com.palm.service.devmode/setDevMode '{"enabled":true}'

Read the Developer Mode passphrase

$ luna-send -n 1 -f luna://com.palm.service.devmode/getPassphrase '{}'

Service menu & factory tools

The factory / service menu (ezAdjust, inStart, inStop). These change deep, undocumented settings and one of them is a factory reset, so treat the whole section as dangerous and know how to undo what you change.

Open a service-menu screen ⚠ dangerous

$ luna-send -n 1 -f luna://com.webos.service.applicationManager/launch '{"id":"com.webos.app.factorywin","params":{"id":"executeFactory","irKey":"inStart"}}'
irKey values: ezAdjust (service menu 1), inStart (service menu 2), inStop (factory reset), pCheck (picture test), sCheck (audio test), tilt (white screen, locks the remote until a reboot), powerOnly. Service menus ask for a code; the common LG one is widely published as 0413. Wrong values here can leave the TV mis-calibrated or wipe it, so write down every value before you change it.

FAQ

What is luna-send?
The command-line client every LG webOS TV ships to talk to the Luna Service Bus, the internal message bus that power, apps, picture, sound, Wi-Fi, notifications and hundreds of other services listen on. A call is a URI (luna://service/method) plus a JSON payload.
Do I need a rooted TV to run these?
To run them, yes: a rooted TV with SSH from the Homebrew Channel, or LG's Developer Mode. Browsing the catalog needs nothing. Private methods need root; Developer Mode's shell is not root.
What's the difference between luna-send and luna-send-pub?
luna-send uses the private bus, luna-send-pub the public one. A few methods are only registered on the public bus, so they need luna-send-pub. When a call says permission denied on one, try the other.
Are these safe to run?
Most just read or nudge the TV. The ones marked dangerous change power, launch or reset state, and the service-menu and factory calls can mis-calibrate or wipe the set. Running one is exactly as safe as typing the same luna-send yourself: read what it does first.
Where can I find every command, not just these?
In the Luna Atlas catalog: thousands of methods across hundreds of services, each with its parameters, access level and a command to run. This cheatsheet is the handful people reach for most.
How were these verified?
Every command here was checked against the Luna Atlas catalog so the service and method exist and the access level is right, then grouped by task and reworded. Parameter shapes come from the catalog, community cheatsheets and real bus traffic.
